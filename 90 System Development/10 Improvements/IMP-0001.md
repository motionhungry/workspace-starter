# Build the v1 starter

## Problem and evidence

The approved design calls for a reusable, domain-independent Obsidian vault that an operator can start and evolve from Claude or ChatGPT. The maintainer repository began with a README and license.

## Outcome and boundaries

Produce an independent vault from the distributable template and guide the operator to a saved first improvement. Set up explicit Git backup, optional external media, and opt-in upstream review. Keep release, compatibility, and pilot evidence in the maintainer repository.

## Proposed change

1. Establish operating instructions, the development record contract, and the brainstorm, development, and workspace skill-creator workflows.
2. Add the first-use prompt, bootstrap, discovery, media and backup setup, and opt-in update review.
3. Exercise setup, resumption, backup failure and recovery, and representative discovery. Record the environments actually tested and the pilot checks still required.

## Acceptance criteria

- A new vault has separate Git history, an inbox, and a system-development area with valid records.
- Resuming preserves work and keeps one first proposal. Saving it requires agreement and implementation uses separate approval.
- An approved checkpoint preserves unrelated work, retains a local commit after a failed push, and verifies the backup on retry.
- Claude and ChatGPT paths have their actual discovery, setup, and fresh-session results recorded. Reopen the vault in Obsidian and verify media access independently.
- In the pilot, Marco can reopen a separate workspace, find his proposal, and carry an approved change through validation.

## Approval

Kyle confirmed the v1 design on 2026-11-19 and requested implementation on a new development branch with validation before each checkpoint commit.

## Validation

### Development foundation

- On macOS, validated all three record types and checked the metadata with an independent YAML parser. The first proposal saved once, survived resumption from the archive, and rejected duplicate, concurrent, and invalid saves.

## Next step

Validate bootstrap and Git backup against an independent test repository.
